# 작업 접수·결과 보관 2차 시험

이 문서는 2차의 독립적인 **로컬 합성 시험** 사용법이다. `job-demo.html`은 Firebase를 불러오지 않는다. `job_service.py`는 127.0.0.1에서만 실행되고 실제 AI 대신 정해진 시험 결과를 만든다. 이후 추가된 기존 화면 연결 방식은 [CONNECTED_TEST.md](CONNECTED_TEST.md)를 따른다.

## 검증 결과

- 저장·소유자 분리·동시 중복 접수·동시 작업 선점·이전 작업 결과 덮어쓰기 거부·실패 정보 제한·저장 실패 후 재호출 방지·대기 한도·서버 중복 실행 방지: Python 8개 시험 통과.
- 실제 로컬 HTTP 서버와 Edge에서 접수 후 완료 전에 브라우저 컨텍스트 종료 → 서버 처리 완료 → 서버 프로세스 종료·재시작 → 새 브라우저에서 같은 작업과 결과 확인 통과.
- 잘못된 접근 코드 거부, 같은 요청 재접수 시 같은 작업 반환, 같은 요청 식별자의 내용 변경 거부 확인.
- 실제 AI 호출 0, 운영 Firestore 쓰기 0, 브라우저 외부 요청 0.

접수된 작업은 SQLite 파일에 저장된다. 서버가 처리 도중 종료되면 해당 작업은 다음 기동 때 ‘중단 · 확인 필요’가 된다. 자동 재호출하지 않는다. 접수 대기 중인 작업은 다음 기동 때 처리하고, 이미 완료한 결과는 그대로 조회한다. 서버가 꺼져 있는 동안에는 처리하지 않는다.

## 로컬 사용

Python 3.12 표준 라이브러리만 사용한다. PowerShell에서 이 폴더로 이동하고 다음을 실행한다. 코드는 이 시험에만 쓰는 임의의 24자 이상 ASCII 문자열이다.

```powershell
$env:YT_JOB_TEST_TOKEN='my-local-synthetic-test-code-12345'
python job_service.py --db ./local-test/jobs.sqlite --ready-file ./local-test/ready.json --port 5066
```

브라우저에서 `http://127.0.0.1:5066/`을 열고 위 접근 코드, 제목, 100자 이상의 시험 자막을 넣는다. 접수 안내가 나오면 창을 닫아도 된다. 서버는 계속 켜 둔다. 다시 같은 주소와 접근 코드로 들어가 ‘작업 불러오기’를 누르면 결과를 볼 수 있다. 종료는 서버 터미널에서 Ctrl+C. 같은 명령으로 다시 켜면 저장된 결과를 확인할 수 있다.

원문 자막도 로컬 DB에 저장되므로 시험용 문장을 사용한다. DB 파일을 GitHub에 올리지 않는다. 접근 코드는 브라우저에 저장하지 않는다. 응답을 받지 못했을 때 같은 화면에서 같은 내용을 재접수하면 같은 요청 식별자를 사용한다. 창을 새로 열면 요청 식별자를 기억하지 않으므로 먼저 작업 목록을 확인한다. 완료 후 새로 접수하면 별도 작업이다.

자동 검증:

```text
python test_job_store.py
node test-job-browser.cjs
```

브라우저 검증에는 Playwright와 Edge가 필요하다. TEST_PYTHON, TEST_PLAYWRIGHT_MODULE 환경변수로 실행 경로를 지정할 수 있다. 시험은 임시 DB를 만들고 종료 시 정리한다.

## 다음 연결 작업

실제 요약 프롬프트·청킹·결과 저장을 서버 작업으로 옮기는 단계가 남았다. 이번 합성 결과는 요약 품질이나 실제 AI 실패 처리를 검증한 것이 아니다. PC 없이 처리하려면 이 작업을 맡을 실행환경과 지속 저장소, 사용자 인증, 비용 통제가 필요하다. 이 로컬 시험 서버를 그대로 공개 배포하지 않는다. records.html, D6, 운영 Firestore 구조는 수정하지 않았다.
