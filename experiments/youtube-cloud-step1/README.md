# 유튜브 PC 독립 운영 준비 — 1차 복사본

3차 추가: 기존 자막 붙여넣기 화면을 로컬 작업 큐와 연결했다. [CONNECTED_TEST.md](CONNECTED_TEST.md)의 `--processor pipeline`으로 실행하면 기존 화면 → 작업 접수 → 서버에서 기존 요약 처리 코드 실행 → SQLite 결과 보관 → 재접속 조회가 이어진다. AI 응답은 합성이며 운영 DB를 사용하지 않는다. 아래는 기본 Flask 방식의 1차 변경 설명이다.

버전: v38-c1-0914. 기존 v38을 복사하여 **화면·API·캡처 주소를 분리**한 검토본이다. 클라우드 배포본이나 PC 독립 운영 완성본은 아니다.

## 바뀐 동작

기존 화면은 API와 자료함·캡처·요약 링크를 localhost:5055에 연결했다. 이제 `connection-config.js`에서 API와 캡처 주소를 지정할 수 있다. 화면 사이 이동은 화면이 호스팅된 위치를 따른다. 빈 설정에서 기존 Flask / 및 /data 경로는 유지한다. 정적 호스팅의 하위 폴더에서는 youtube.html/data.html을 사용한다.

자막 직접 넣기, AI 프롬프트·모델, 청킹, Firestore 저장 구조, 기록보관실 연동, 메모·책갈피 기능은 유지한다. 기존 서버 함수는 변경하지 않았고, 두 연결 JS 파일만 제공하는 라우트와 버전 표기를 추가했다. ai_cost.py·오타사전은 원본 그대로다. 키·비용 장부 JSON·캐시·캡처·요약 데이터는 복사하거나 포함하지 않았다.

## 검증

- Node 주소 검증: 기본 localhost, 다른 로컬 포트, 기존 LAN, HTTPS 하위 폴더, 자료함, file 경로, API/이미지/화면 분리, 잘못된 주소 거절.
- HTML 인라인 스크립트 6개 문법 검사 통과.
- Edge headless 실제 브라우저에서 두 환경 시험 통과: 붙여넣기 버튼 → 요약 → 시험용 저장. 이때 `/api/meta` 요청 0, 요청 대상 서버 일치, 본문 전달 확인.
- 두 환경의 자료함: 기존 합성 책갈피·캡처 주소·요약 돌아가기 링크 확인.
- Python 구문 검사 및 원본 서버 함수 AST 동일성 확인. 운영 원본 파일 해시·비용 코드·오타사전 불변 확인.
- 브라우저 시험은 모든 요청을 가로채 가짜 응답을 반환하거나 차단했다. Firebase SDK와 DB도 메모리상의 가짜 구현이다. 실제 외부 AI 호출 0, 운영 Firestore 읽기·쓰기 0.

주소·구문 시험: `node test-connections.cjs`.
브라우저 시험: Playwright와 Edge가 있는 환경에서 `node test-browser.cjs`. 필요하면 TEST_PLAYWRIGHT_MODULE을 설치된 Playwright 모듈 경로로 지정한다. 이 시험은 실제 서비스를 연결하지 않는다.

## 아직 하지 않은 것

실제 Flask 서버 기동은 이번 환경에 Flask가 없어 수행하지 않았다. 실제 원격 API, CORS·인증, Firestore 권한, 유튜브 재생·캡처 성공, 외부 비용 기록은 이번 모의시험으로 보장하지 않는다.

현재 복사본 자체는 기존의 운영 Firebase 설정을 포함한다. 시험 스크립트 밖에서 HTML을 직접 열면 실제 Firebase 접속이 일어날 수 있다. 운영 파일 교체용으로 바로 사용하지 말고 검토용 브랜치에서 개발을 이어간다.

이 복사본의 기존 Flask 서버를 그대로 공개 배포하지 않는다. 클라우드용 인증·비용 통제가 별도로 필요하다. 주소를 바꾸는 것만으로 클라우드 서버가 만들어지지 않는다. 별도 로컬 시험 서버에서는 브라우저 종료 후 작업·결과 보관을 검증했지만 기본 Flask 방식에는 적용되지 않는다. 저장된 요약 본문의 예전 절대 이미지 URL은 이번에 일괄 수정하지 않았다.

다음 구현: 자막 붙여넣기 사용을 유지하면서 클라우드의 인증된 작업 접수 → AI 처리 → 결과 영구 저장·재접속 복구를 만든다. 캡처·이미지 원본은 독립적인 이전 범위로 보존한다. 외부 자막 서비스 도입은 이 작업의 선행 조건이 아니다.
