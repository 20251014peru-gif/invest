# 기존 화면과 작업 서버 연결 — 3차

기존 `자막 직접 넣기` 버튼을 작업 서버에 연결했다. 제목·채널·게시일·영상 주소·자막·타임라인·챕터 선택을 접수하며, 사용자의 브라우저를 닫아도 서버가 처리하고 결과를 SQLite에 보관한다. 재접속 후 같은 접근 코드를 입력하고 `작업 불러오기` → `결과 열기`로 확인한다.

## 실행

Python 3.12, Node, Playwright, Edge가 필요하다. 이 폴더에서 다음을 실행한다.

```powershell
$env:YT_JOB_TEST_TOKEN='my-local-synthetic-test-code-12345'
python job_service.py --db ./local-test/jobs.sqlite --ready-file ./local-test/ready.json --port 5066 --processor pipeline
```

`http://127.0.0.1:5066/youtube.html`을 연다. 위 접근 코드를 입력하고 기존 `자막 직접 넣기` 버튼에서 300자 이상의 시험 자막과 제목·채널을 넣는다. `접수 완료`가 표시된 뒤 창을 닫아도 된다. 서버를 끄면 처리는 멈추며, 다시 켜면 대기 작업은 처리하고 중단된 작업은 확인 필요 상태로 남긴다. 완료된 결과는 다시 조회할 수 있다.

실행 경로가 자동 인식되지 않으면 TEST_NODE에 Node 실행파일 경로, TEST_PLAYWRIGHT_MODULE에 Playwright 모듈 경로를 지정한다. 자동 검증은 TEST_PYTHON으로 Python 실행파일도 지정할 수 있다.

## 실제 연결 범위

- 기존 HTML의 자막 정리·프로필 프롬프트·청킹·최종 요약·본문 후처리·타임라인 책갈피 코드를 서버 작업에서 실행한다.
- 현재는 기존 처리 코드를 그대로 재사용하기 위해 서버에서 별도의 보이지 않는 Edge를 실행하는 과도기적 구조다. 사용자 브라우저와 독립적이지만, 가벼운 서버 전용 요약 엔진으로 분리한 완성본은 아니다.
- 작업 실행 브라우저의 모든 네트워크 요청은 가짜 응답 또는 차단으로 처리한다. AI SDK·실제 AI API·운영 Firestore를 연결하지 않는다.
- 채널 프로필은 작업별 가짜 DB에서 새로 생성한다. 운영 채널 프로필·직전 요약을 가져오거나 작업 사이에 재사용하지 않는다. 누적 판단노트 갱신은 제외했다. 캡처·영상 재생·기존 자료함·기록보관실 저장은 이 시험 범위에 없다.
- 결과 본문·메타·책갈피는 실제 로컬 DB에 보관한다. 결과 보기는 스크립트를 실행할 수 없는 별도 프레임이다. 접근 코드는 브라우저에 저장하지 않는다.
- 기본 Flask에서 열면 기존 동작을 유지한다. 작업 서버에서만 안전한 시험용 저장 구현과 접수 화면을 주입한다. 따라서 시험은 위 주소에서 한다.

## 검증

`node test-connected-browser.cjs`: 실제 기존 붙여넣기 화면 → 27,000자 자막 접수 → 완료 전 브라우저 종료 → 서버 처리 → 서버 재시작 → 새 브라우저에서 결과 열기 통과. 제목·채널·게시일·영상 ID, 타임라인 책갈피 0초/60초 보존, 프로필·복수 청크·최종 요약 단계 실행, 자막 추출 요청 0을 확인했다.

`python test_job_store.py`: 저장·동시 처리·중복·실패·복구·메타 검증 9개 통과. 기존 주소·HTML 문법·브라우저 붙여넣기 시험도 통과했다. 실제 AI 호출 0, 운영 Firestore 쓰기 0. 실제 요약 품질과 본문 완전성은 검증하지 않았다.

처리기 시간 제한은 90초다. 시간초과 시 Node/브라우저 프로세스 트리를 종료하고 회수한 뒤 실패 처리한다. 종료 실패는 작업 처리기를 중단시키며 신규 접수를 거부한다. 공개 클라우드 운영 전에는 처리기 분리, 지속 저장소, 사용자 인증, 비용 통제와 운영 데이터 연계가 남아 있다. 원본·records.html·D6는 변경하지 않았다.
