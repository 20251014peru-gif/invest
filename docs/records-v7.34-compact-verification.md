# v7.34 간단 입력·종목 기록 분류·로그인 안내

점검일: 2026-09-22. 운영 주소: https://20251014peru-gif.github.io/invest/records.html?v=7.34.0

## 변경 사항과 사용법

- 종목에서 `기록 남기기`를 누르면 **종목 기록**으로 저장한다. 이전에는 코드가 메모를 기본값으로 지정했다. 저장 분류와 연결 종목을 입력창과 저장 버튼에 표시한다. 새 탭을 늘리지 않고 기존 종목 화면과 전체 목록에서 확인한다.
- 이미 저장된 메모는 자동 변경하지 않는다. 원하는 기록을 열어 `수정 → 종류 변경 → 종목 기록`으로 바꿀 수 있다. 종목이 없는 종목 기록은 저장 전에 종목 추가를 안내한다.
- 기록 입력은 **남길 내용 / 종목·날짜** 두 열이다. 제목은 선택, 내용·사진·링크 중 필요한 것을 남긴다. 판단·출처·중요도·주제·시나리오는 `추가 정보`를 펼쳐 작성한다. 접힌 기존 값도 그대로 저장한다.
- 확인할 일은 **질문 / 종목·예정일**만 먼저 입력한다. 확인 후 같은 항목의 `결과 남기기`를 펼친다. 판단·예상 비교·복기는 선택 입력이며 기존 내용을 보존한다. 결과 없이 완료하거나 보류하면 해당 입력을 펼쳐 안내한다.
- 같은 입력 공간에서 `기록 / 확인할 일 / 종목 정보`를 전환한다. 반복된 ①②③과 세 개의 큰 입력 열을 없앴다. 작성 중 전환·닫기는 기존 보존 확인을 거친다.
- Google 로그인 상태에서 기존 `본인 로그인` 버튼은 아무 작업도 하지 않았다. 이제 `Google 계정` 버튼이 현재 계정과 서버 연결 안내를 연다. `Google 계정 선택`으로 다시 선택하고, `연결 확인`으로 기록 접근 권한을 확인한다. 팝업 차단·취소·네트워크 오류는 화면에 남는다. 취소 전에 기존 계정을 로그아웃하지 않는다. 계정 선택 중 작성 내용이 있는 경우 먼저 저장·닫기를 안내한다.
- 종목 화면의 3열 요약, 가로 A4 2/3열 출력은 유지한다. 작은 화면에서 입력은 1열로 전환한다.

## 검증

- Node 시험 81개 통과: 원본 보존·백업·사진·연결·종목 이력·충돌·확인 상태·연구실 호환.
- 기록 흐름, 확인·복기, 간단 배치, 계정 안내 브라우저 시험 통과. 외부 Firebase 호출을 막은 대역으로 저장 실패·재시도·중복 방지·다른 창 수정 충돌을 확인했다.
- 새 종목 기록 분류, 기존 메모 수 불변, 종류 변경 시 본문 유지, 접힌 상세 저장, 입력창 전환 취소 시 글 보존, 계정 선택 취소 시 세션 유지, 로그인 오류 안내를 확인했다.
- 1536/1024/768/390px 화면 및 가로 2/3열 출력 확인. 실제 휴대폰·실물 프린터 시험은 아니다.

- 별도 개발 화면에서 기존 소유자 Google 세션으로 서버 접근, 새 **검증용** 종목 기록 저장, 재접속 후 분류·본문 조회를 확인했다.
- 검증용 완료 확인의 다음 행동만 수정하고 저장했다. 접힌 예상·판단·출처·기존 결과가 유지되는지 원본 문서로 대조했다.
- 기준 백업: `test-results/live-deployment/snapshot-1790040887482.json`. 사후: `snapshot-1790041046705.json`. 개인 백업은 Git에서 제외한다.
- 대조 결과: 기존 12개 기록, 종목 정보, 할 일, 다른 확인 항목 불변. 검증용 종목 기록 1개와 해당 확인의 변경 이력 1개 추가. 기존 검증용 확인의 `nextAction` 및 저장 메타데이터만 변경.
- 계정 버튼 안내와 실제 서버 접근 성공. Google 계정 선택 팝업 개방은 확인했다. 개발 화면의 팝업 선택 후 완료 회신은 브라우저 제어 지연으로 확인하지 못했으며 기존 로그인 세션을 이용했다. 운영 확인 결과는 아래에 별도 기록한다.

## 운영·백업·복구

- 화면은 기존 GitHub Pages, 공통 자료는 기존 Firebase `my-system-25497`의 Firestore, 사진은 기존 Firebase Storage를 사용한다. 새 서버·요금제·AI 호출·예약 작업은 없다. 기존 GitHub/Firebase 사용량에 따른 비용 구조를 유지한다.
- 운영 데이터 컬렉션은 `records`, `records_meta`, `records_todos`, `record_followups`, `record_followup_reviews`. 접근 규칙과 소유자 권한은 변경하지 않았다. 클라이언트의 Google 계정 표시를 서버 소유권 검증으로 간주하지 않는다.
- 백업에서 기존 검증용 사진 1개의 URL은 보존했지만 사진 바이트는 CORS 제한으로 누락되어 있다. 문서 백업을 사진 전체 백업이라고 표현하지 않는다. 원본 사진 삭제·이동은 없다.
- 코드 복귀 기준은 v7.33의 `bca0d11`. 새 `stock` 분류가 존재하므로 구버전으로 돌릴 때 이 분류의 표시 호환성을 확인하고, 원본 문서를 메모로 일괄 덮어쓰지 않는다. 데이터 복구는 필요한 ID만 백업과 대조해 수행한다.
- 실제 휴대폰·외부 이동통신망·서로 다른 PC 동시 사용, 과거 유튜브 원본 링크 전체와 다른 프로그램의 예약 작업은 이번 시험 범위 밖이다.
