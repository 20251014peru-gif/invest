## 실제 Firebase 검증과 자료 보존

본인 Chrome 로그인으로 실제 `my-system-25497` 프로젝트에 연결한 개발 화면에서, 이전에 만든 `[검증전용] 통합화면` 항목만 사용했다.

1. 일반 기록의 핵심 한 줄을 새 입력창에서 수정·저장하고 읽기 화면 반영을 확인했다.
2. 검증용 종목의 관심 이유를 나란히 배치된 입력창에서 수정·저장했다.
3. 기존 검증용 확인 항목의 다음 행동을 수정·저장했다. 완료 상태와 기존 결과는 유지했다.
4. 전후 스냅샷을 깊은 비교했다. 일반 기록 1개, 종목 메타의 검증용 종목 1개, 검증용 확인 1개만 변경됐고 확인 이력 1개만 추가됐다. 다른 모든 기록·종목·할 일·확인과 기존 이력, 원래 사진 주소/첨부 정보는 같았다. 기록 12개, 확인 40개 수는 유지됐다.

최신 백업은 공개 Git에서 제외된 `test-results/live-deployment/snapshot-1790036990252.json`, 검증 후 대조본은 `snapshot-1790037244549.json`이다. 백업 사진 1개는 기존 CORS 제한으로 바이트 수집이 실패했다. 이 사진은 앞선 작업의 합성 시험 이미지이며 원본 첨부 정보는 보존됐다. 따라서 사진 전체 백업 완료로 표기하지 않는다.

## 운영·복구

GitHub Pages 정적 화면과 기존 Firebase Authentication/Firestore/Storage를 그대로 사용한다. 운영은 사용자 PC나 개발 서버가 켜져 있을 필요가 없다. 이번 변경에 예약 작업·새 서버·새 유료 서비스는 없다. 기존 Firebase 사용량에 따른 비용 구조를 바꾸지 않았다.

코드 문제는 이번 UI 변경 커밋만 되돌려 이전 v7.32.0 화면을 다시 배포한다. 자료 구조를 변경하지 않아 데이터 역변환은 필요 없다. 다른 사용 중 변경을 지우는 전체 스냅샷 덮어쓰기는 하지 않는다. 개인 JSON과 사진은 공개 저장소에 올리지 않는다.

과거 유튜브 원본 링크 5건의 localhost 의존과 전체 사진 백업 문제는 [이전 검증 기록](records-v7.32-live-verification.md)의 미해결 범위이며 이번 UI 개선으로 해결됐다고 주장하지 않는다.



배포 요청 기록: 2026-09-22, v7.33.0 입력·출력 개선 코드와 실제 Firebase 저장·재조회 및 원본 대조를 확인한 뒤 기존 main의 GitHub Pages 배포를 요청했다. 자동 검사도 통과했다.
