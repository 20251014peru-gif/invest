# 🗂 가볍게 기록하고 연결하며 발전시키기 (기록보관실 v7.28)

작성: 2026-09-17(v7.28.0) · 갱신: 2026-09-17(v7.28.1 — 사진 임시저장·전체 백업/복원)
코드: `records.html`, `js/records-core.mjs`, `js/records-drafts.mjs`, `js/records-backup.mjs`, `js/study/study-app.mjs`·`study-editor.mjs`·`study-core.mjs`(작은 확장)
시험: `tests/records-core.test.mjs`, `tests/records-drafts.test.mjs`, `tests/records-backup.test.mjs`, `tests/study-browser/`

## 1. 목적과 범위
투자 공부·일상적인 생각·나중에 볼 질문·사진·링크를 사진 한 장·문장 하나만으로도 가볍게 남기고, 나중에 서로 연결하거나 새 생각으로 이어 쓰거나 여러 자료를 모아 공부노트/아이디어로 정리할 수 있게 한다. 종목은 선택 가능한 연결 대상일 뿐 모든 기록의 중심이 아니다. 공부노트(`kind=study`, v7.27.2)와 기존 데이터·저장 계약은 그대로 두고, 유튜브/뉴스/아이디어/차트/메모 5종 + 종목 등록의 작성 경험만 다시 짰다.

## 2. 종류별 작성창 — 전/후
공통: 사진 추가는 모든 작성창에서 항상 보이고(추가 속성 안에 숨지 않음), 제목·본문·링크·사진 중 하나만 있어도 저장된다. "+ 기록 추가"는 지금 보고 있는 탭 종류로 바로 열린다(예전엔 항상 유튜브로 열렸다 — 버그 수정). "전체" 탭에서 누르면 메모로 즉시 시작.

| 종류 | 이전 1차 화면 | v7.28 1차 화면 | 추가 속성(접힘) |
|---|---|---|---|
| 메모 | 제목 필수, 핵심1줄, 본문 | 제목(선택)·사진·내용 | 채널, 종목, 주제, 액션(없음), 별점, 검증, AI해석/내판단, 나중에 볼 것 |
| 아이디어 | 제목 필수, 핵심가설, 근거 | 제목(선택)·사진·떠오른 생각·이유·배경(선택) | 위와 동일 + 시나리오(상승/중립/하락, 투자 판단으로 발전시킬 때만) |
| 차트 | 제목 필수, 관찰포인트, 링크, 분석 | 제목(선택)·**사진을 본문보다 위에 크게**·관찰·궁금한 점(선택) | 출처 링크, 채널, 종목, 주제, 액션, 별점, 검증 등 |
| 뉴스 | 제목 필수, 핵심1줄, 매체, 링크, 본문 | 제목(선택)·사진·본문(남겨둘 내용)·**기사 링크** | 매체, 종목, 주제, 액션(호재/악재), 별점, 검증 |
| 유튜브 | 제목 필수, 핵심1줄, 채널, 링크, 본문 | 제목(선택)·사진·본문(남겨둘 내용)·**영상 링크** | 채널, 종목, 주제, 액션, 별점, 검증 |
| 종목 등록 | 이름만(변경 없음) | 이름 + `관심 이유` 프리셋이 "추가 정보"에 맨 앞으로 | 목표가·보유수량·매수단가·상태는 여전히 접힌 details |

- 제목이 비면 저장 시 **1회만** 자동 채움: 본문 첫 줄(40자) → 사진만 있으면 "사진 기록 · 날짜(N장)" → 링크 도메인 → 종류 이름. 사용자가 적은 제목은 절대 덮지 않고, 재편집 때 재생성하지 않는다.
- "추가 속성"은 `<details>`로 **DOM을 그대로 둔 채 시각적으로만 접는다** — 기존 `fVerify`/`fAiInterp` 등 읽기/쓰기 코드를 100% 재사용해 값 손실 위험이 없다. 편집창을 열면 "기존 추가 정보 N개" 배지로 있는지 알려준다.
- 종류 전환은 상단 탭 나열 대신 "⋯ 다른 종류로" 뒤에 접어두고, 전환해도 본문·사진·주제는 그대로 남는다(값을 지우지 않으므로).

## 3. 모든 종류 공통 다중 사진 첨부
- `attachments[]`: `{id, path, url, name, size, type, caption, order, addedAt}`. 저장 시 `image`/`imagePath`를 **대표 사진(첫 장)의 투영**으로 계속 채워 갤러리뷰·종목 표지(`stockCoverImage`)·검색 등 구버전 소비 경로를 그대로 호환한다. `js/records-core.mjs`의 `getAttachments(r)`가 신규/구버전(단일 `image`)을 한 형태로 읽어 모든 렌더링이 이 함수만 거치므로 같은 사진이 중복 표시되지 않는다.
- Storage 경로: `records_images/<KST날짜>/rec_<id>.<확장자>` — 공부노트(`study_<id>`)와 같은 상위 폴더 규칙, prefix만 다르다. 8MB 제한.
- PC: 파일 선택(여러 장)·붙여넣기(Ctrl+V)·끌어놓기. 모바일: "사진 선택" 버튼이 OS 기본 촬영/갤러리 선택기를 그대로 띄운다(별도 카메라 UI는 만들지 않음 — 지원 한계로 명시).
- 파일별 업로드 상태(업로드 중/완료/실패)를 썸네일에 바로 표시. 동시 업로드 3개로 제한(모바일 정지 방지). 실패한 파일은 "재시도/제거" 버튼이 항상 보이고, 업로드 중이거나 실패한 사진이 있으면 저장을 막는다(자동 무시 없음).
- 순서는 ▲▼ 버튼으로 바꾼다(끌기 재정렬은 이번 범위 밖 — §9). 대표 사진은 ★로 지정, 설명(캡션)은 선택 입력. 클릭하면 확대(`#attZoomModal`).
- HEIC 등 브라우저가 미리보기를 못 그리는 형식은 업로드는 시도하되 "미리보기를 지원하지 않을 수 있어요" 안내를 남긴다(조용히 버리지 않음).
- **삭제 정책 변경**: 기록 삭제·사진 교체 때 더 이상 Storage 파일을 즉시 지우지 않는다(공부노트와 같은 정책으로 통일 — 복원 여지를 남김). 안 쓰는 파일 정리는 후속 과제.
- **미업로드 사진 임시 저장(v7.28.1)**: `js/records-drafts.mjs`가 IndexedDB(base64 미사용)에 상태 바뀔 때마다(0.6초 디바운스, `pagehide` 때 즉시) 첨부 목록을 저장한다 — 이미 Storage에 올라간 것은 URL만, 아직 안 올라갔거나 실패한 것은 재시도용 원본 Blob까지. 작성창을 다시 열면(새 글은 `new`, 수정 글은 그 기록 id로) "저장하지 못하고 남아있던 사진 N장 — 이어서 쓸까요?" 배너가 뜨고, 이어서 쓰기를 고르면 완료분은 그대로, 미완료/실패분은 자동 재업로드된다. IndexedDB를 못 쓰는 상황(사생활 보호 모드 등)은 조용히 넘어가지 않고 "이 기기에 임시 저장할 수 없어요 — 새로고침하면 다시 선택해야 해요"로 명확히 알린다. 저장 성공 시 임시분은 지운다.
- 반영 범위: 카드뷰(작은 대표 썸네일), 갤러리뷰(대표 사진 + "+N"), 상세 화면(사진 전체 + 설명), 종목 표지. 리스트/표/보드/채널/달력/타임라인뷰는 기존처럼 텍스트 전용으로 남겨뒀다(레이아웃 위험 최소화).
- **내보내기·복원(v7.28.1)**: 상세 화면 "⬇ 기록 파일로 내보내기" / 툴바 "♻ 기록 복원". 공부노트와 별개로 일반 기록(youtube/news/idea/chart/memo) 전체를 대상으로 하며, 사진을 실제 파일(base64)로 담고 순서·설명·대표사진·`relations[]`·`checks[](나중에 할 일)`를 필터 없이 그대로 포함한다(`js/records-backup.mjs`). 복원은 항상 **새 기록**으로 생성(기존 기록을 덮어쓰지 않음) — 사진은 새 Storage 경로로 재업로드하고, 파일에 없는 사진은 원본 주소가 아직 열리는지 확인한 뒤 열리면 연결, 안 열리면 `status:'missing'`으로 자리·설명을 남긴다(조용히 빠뜨리지 않음).

## 4. 기록을 발전시키는 세 가지 행동 (상세 화면)
1. **관련 기록 연결** — 기존 `openRelModal`/`addRelation`(트랜잭션 병합, 동시 편집 안전) 그대로. 선택지: 관련 있어요(기본)·참고했어요·**생각의 출발점**(신규)·뒷받침·반대 근거. 종목 선택을 거치지 않고, 같은 주제라는 이유로 자동으로 지지/반박 관계를 만들지 않는다.
2. **이어서 생각하기** — 메모/아이디어를 골라 새 기록을 만든다. 원본은 바뀌지 않고, 새 기록이 `relations:[{type:'derived_from', targetId:원본}]`를 가진 채 **단일 문서 쓰기**로 저장된다(미리 만든 문서 id 하나로 `.set()` — 원자적, 재시도해도 같은 문서만 덮어써 중복 생성 없음). 취소하면 아무것도 안 남는다. 원본 페이지엔 "이 기록에서 생각이 이어짐"으로 역방향 표시.
3. **모아 정리하기** — 상세 화면에서 시작(현재 기록이 첫 근거로 미리 담김), 검색으로 기록을 더 추가한 뒤 공부노트/아이디어를 고른다. 아이디어는 빈 작성창(제목/내용)에 `relations:[{type:'synthesizes', targetId:각 원본}]`을 담아 단일 쓰기. 공부노트는 `js/study/study-app.mjs`의 새 `newNoteWithRelations()`(작은 확장)로 전용 편집기를 열되 관계를 미리 채워두고, **저장은 사용자가 직접** 눌러야 실제로 반영된다(원문 자동 복제·AI 요약 없음 — 직접 정리). 선택한 원본은 수정·삭제되지 않는다.
- 신규 관계 타입 `derived_from`/`synthesizes`는 `records.html`의 `REL_TYPE_LBL`/`REL_REV_LBL`과 `js/study/study-core.mjs`의 `RELATION_TYPES`에 **둘 다** 등록했다(공부노트 저장 경로가 모르는 타입은 `related`로 낮추기 때문 — 처음엔 이 문제로 타입이 깎이는 걸 실제로 발견해 고쳤다).
- 관련 기록 연결/이어서 생각하기/모아 정리하기 모달은 상세 화면(`#pageModal`) 위에 열리므로 z-index를 올렸다 — 같은 문제가 기존 "+ 연결"에도 잠재해 있던 것을 이번에 같이 고쳤다(§8 참고).

## 5. "🕒 나중에" 통합 보기
- 자료 종류와 무관한 특수 탭(`laterMode`, "🏷 종목"과 같은 방식). 새 kind·새 컬렉션 없음.
- 기존 `checks[]`(날짜/빈 날짜 전부, 이전엔 "오늘의 체크리스트"가 오늘 날짜만 봤다)와 공부노트 `studyNeedsReview`(재검토 필요, 읽기 전용 행 — 상태 변경은 공부노트 편집기에서만)를 한 목록으로 모은다. `js/records-core.mjs`의 `collectDueChecks()` 하나를 "오늘의 체크리스트" 위젯과 이 통합보기가 같이 써서 중복/불일치가 생기지 않는다.
- 완료 처리는 기존 `records_todos` 완료마커(`dueKey=레코드id#체크id`)를 그대로 재사용 — 새 완료 메커니즘 없음. "다시 열기"는 그 마커 문서를 지운다.
- 필터: 미완료/완료/전체, 행동(알아보기/더 생각하기/다시 읽기/기타), 주제. **기한 없음 항목은 미완료 목록에서 빠지지 않는다.**
- 상세 화면 "🕒 나중에 볼 것 + 추가"로 날짜(선택)·행동·짧은 메모를 그 자리에서 바로 남길 수 있다(`checks[]`에 `firebase.firestore.FieldValue.arrayUnion`으로 추가 — 읽기 없이 붙이므로 동시 저장 충돌이 없다).
- 달력 🔔에 공부노트 재검토일도 같이 표시(이전엔 `checks[]`만 읽어 `reviewAt`은 전혀 안 보였다).

## 6. 저장 계약 — 무엇이 추가됐나
`records` 컬렉션(기존과 같은 곳)에 전부 **추가 전용** 필드:
- `attachments[]`(§3), `checks[].id`/`checks[].followUpType`(신규 항목에만, 기존 항목은 인덱스 기반 유지 — 기존 완료 표시가 어긋나지 않게).
- `relations[]`에 `derived_from`/`synthesizes` 타입 추가(기존 5종 보존).
- stockMaster 항목에 `관심 이유` 프리셋 추가(값 변경 시 기존 `thesisLog` 자동기록 재사용).
- 검색(`curQ`)이 사진 설명·`checks[].what`도 훑는다(이미지 속 글자 OCR은 대상 아님).
- 기존 데이터는 전부 안전한 기본값으로 읽는다(`attachments` 없으면 `image`에서 합성, `checks[].id` 없으면 인덱스로 대체) — 운영 일괄 이행 없음.

## 7. 비용 영향
새 유료 API·AI 호출·새 서버 없음(공부노트와 같은 원칙). 비용이 늘 수 있는 곳:
- **Storage**: 사진마다 원본 파일 크기 그대로 저장(압축 없음), 자동 삭제를 껐으므로(§3) 누적 용량이 이전보다 더 빨리 늘어난다. 첨부 여러 장을 쓰는 기록이 많아질수록 체감이 커진다.
- **Firestore 쓰기**: "나중에 볼 것" 완료/다시열기 1회 = `records_todos` 쓰기 1(기존 오늘 위젯과 동일 비용 구조). 상세 화면 "나중에 추가" 1회 = `records` 문서 업데이트 1(`arrayUnion`, 읽기 없음). 이어서 생각하기/모아 정리하기(아이디어) 1회 = 새 문서 쓰기 1(관계 포함, 원본 쓰기 없음).
- **실시간 구독**: 기존과 동일하게 `records` 전체를 구독하므로, 문서당 `attachments[]` 배열이 늘어난 만큼 전송량이 조금 커진다(사진 자체는 URL만 저장되므로 개수·설명 텍스트 정도의 증가).
- 실제 운영 요금은 Firebase 콘솔에서 확인.

  - 종류 전환 시 본문·사진 유지, "+ 기록 추가"가 탭 종류로 바로 열림.
  - 기존 별점(4)·액션·검증상태·AI해석·내판단·종목·주제·채널이 있는 기록을 열었다 그대로 저장 → 전부 보존, "기존 추가 정보 8개" 배지 정확.
  - 구버전 단일 `image` 기록을 열면 1장짜리 첨부로 자동 변환되고, 저장하면 `attachments[]`+`image` 투영이 함께 채워짐.
  - 사진 실제 업로드(모의 Storage) → 상태 전이(업로드 중→완료), 카드 썸네일·상세 화면 표시.
  - 이어서 생각하기: 저장→새 문서(`derived_from`) 생성·원본 미변경·양방향 이동, 취소 시 문서 미생성.
  - 모아 정리하기→아이디어: 2개 원본 선택→`synthesizes` 관계 2개로 저장, 취소 시 미생성.
  - 모아 정리하기→공부노트: `newNoteWithRelations` 프리필→저장 후 `relations[].type==='synthesizes'` 확인(첫 시도에서 `related`로 깎이는 문제 발견·수정, §4 참고).
  - 나중에 볼 것: 상세에서 추가(`arrayUnion`)→통합보기에 기한없음으로 노출→완료→미완료 필터에서 사라짐→다시 열기→다시 보임.
  - 모바일 뷰포트(375×812) 흉내: 새 작성창이 가로 스크롤 없이 렌더링, 사진 추가 항상 보임, 추가 속성 접힘 — **"개발 측 확인(실기기 아님)"** 등급, 실제 휴대폰 확인 아님.
  - `tests/study-browser/regression.html`(공부노트 서식·MarkFlow 회귀) 6/6 통과 — `study-editor.mjs`의 `prefill.relAdd` 추가가 기존 동작을 깨지 않음을 확인.
