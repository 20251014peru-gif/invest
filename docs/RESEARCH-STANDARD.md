# 공통 기본 보기 규칙 v1

사용자 확정: 2026-09-13. 첫 적용: 투자 통합분석실 CPI.

## 역할과 흐름
- 1페이지: 핵심 변화, 관련 공식 발표·뉴스, 내 분석, 다음 확인사항.
- 2페이지: 선택한 자료 또는 자료 모음. 1페이지에서 충분히 설명하지 못한 중요한 내용.
- 3페이지: 추가 설명·비교·세부 근거. 특정 자료 종류나 개인 분석 전용으로 고정하지 않는다.
- 탐색은 왼쪽에서 오른쪽, 근거를 핵심 정리에 채택하는 흐름은 오른쪽에서 왼쪽이다.
- 중요도에 임의 점수를 부여하지 않는다. 직접 고정·공식 발표·검토일 등 이유를 표시한다.
- 결론을 바꾸는 반대 근거와 중요한 미확인은 1페이지에도 표시해야 한다. 숨겨진 자료를 근거로 단정하지 않는다.

## 열기와 보존
- 기본 2페이지, 최대 3페이지. 같은 자료는 중복 창을 만들지 않는다.
- 4번째 창을 만들지 않고 마지막 페이지를 교체한다. 작성 중인 초안은 페이지 교체와 무관하게 보존한다.
- 모든 페이지에 전체 페이지 확대와 이전 배치 복원을 제공한다.
- 좁은 화면에서는 앞쪽을 접고 열린 페이지 목록에서 복귀한다. 문자를 줄여 세 칸을 강제하지 않는다.
- 카드·리스트·표 등 보기 전환은 자료 모음에 적용한다. 8개 기존 보기는 records.html에 유지한다. CPI 첫 적용에서는 카드·표를 제공한다.

## 자료와 소유권
- 공식 CPI 확인본은 data/research-cpi.json. 원문 URL, 발표 기준기간, 발표시각, 확인시각, 다음 공식 일정을 저장한다.
- 이 확인본은 자동 갱신하지 않는다. 파일과 화면에서 확인일 및 고정 확인본임을 알리고, 예정일이 지나면 새 발표 확인 필요를 표시한다.
- 전월비는 계절조정, 전년비는 비계절조정으로 구분한다. 월별 단일 CPI 값을 OHLC 봉으로 만들지 않는다. 공식 중립선 미확인은 선을 표시하지 않는다.
- 첫 단계 관련 뉴스는 기존 records의 topics에 CPI가 연결된 뉴스만 보여준다. 외부 뉴스를 임의 수집·중복 저장하지 않는다.
- 공식 원자료와 사용자 분석은 별도. 공식 근거는 ID와 URL로 연결하고 개인 분석의 사용자 판단 칸에 저장한다.

## 저장·로그인·복구
- 기존 records.html과 같은 Firebase 프로젝트, 인증, records 컬렉션을 이용한다. 기존 인증·접근 규칙은 변경하지 않는다. 새로운 개인별 보안 격리를 제공한다고 주장하지 않는다.
- 데이터 형식: 기존 idea / schemaVer 2 필드를 유지하고 researchEvidence, researchRevision, researchHistory, researchTopicId를 추가한다.
- 저장은 명시적인 버튼에서만 실행한다. 렌더링·포커스·새로고침은 클라우드 쓰기를 발생시키지 않는다.
- 초안은 invest.research.cpi.workspace.v1에 로컬 보관한다. 이 브라우저에 저장됨과 기록보관실 저장됨을 구분한다. 초안 내려받기를 제공한다.
- 신규 문서 ID는 초안 생성 때 고정한다. 재시도는 동일 operation ID로 중복 저장을 막는다.
- 트랜잭션에서 원격 내용 지문을 비교하여 다른 화면의 수정은 덮어쓰지 않는다. 충돌 시 현재 초안을 별도 기록으로 저장할 수 있다.
- 수정 시 이전 분석·채택 근거를 researchHistory에 보존한다. 기존 종목·별점·검토일·원래 기록일 등은 보존한다. 이력이 커져 서비스 제한에 도달하면 쓰기 실패를 표시하고 원격 원본과 초안을 보존한다.
- 각 분석의 주소: research-cpi.html?record=<record ID>. 기존 기록보관실은 같은 문서를 그대로 읽는다.

## 이번 범위와 확장
- 기본 research.html에 CPI 작업창을 연결하고 macro.html, chatgpt/, records.html 독립 주소를 유지한다.
- 공통 상태·날짜·기록 변환은 research-core.mjs, 기존 기록 연결은 research-records.mjs로 분리한다.
- 자동 공식 발표 수집, 뉴스레이더의 CPI 주제 자동 연결, 모든 지표 이관, 전체 8개 보기 재구현은 이번 첫 적용 범위 밖이다.
- 검증 기준: 2→3페이지, 전체→복원, 새로고침 초안 복구, 저장 실패·충돌·재시도, 기존 기록 필드 보존, 좁은 화면, 기존 독립 화면 연결.

## 배포·롤백
- 연구 화면만 기존 버전으로 복구할 수 있다. records 데이터와 researchHistory를 삭제하지 않는다.
- 공개 저장소에는 코드와 공식 자료만 포함한다. 개인 분석 본문과 실제 계정 식별자는 변경 이력에 기록하지 않는다.
# 전체 대시보드 적용 · v018

- 진입 주소: research.html 기본 화면 → research-dashboard.html. CPI 전용 화면과 기존 #macro, #analysis, #records 주소는 유지한다.
- 1페이지는 전체 목록과 선택한 핵심, 2페이지는 선택 자료, 3페이지는 출처 또는 명시적으로 연결된 기록이다. 새로운 자료를 선택하면 2·3페이지 맥락을 초기화한다. 3페이지 안에서 연결 자료를 열어도 4페이지를 만들지 않는다.
- 카드·목록·표·종류 보드·주제별·달력·타임라인·갤러리는 동일한 자료·필터를 공유한다. 갤러리는 저장된 문장·지표 흐름의 큰 미리보기이며 임의 이미지를 생성하지 않는다. 월간 자료를 달력의 임의 날짜에 넣지 않는다.
- 지표 ID는 indicator:원래ID, 기록 ID는 record:Firestore문서ID다. 데이터 소유권과 원본 저장소는 변하지 않는다. 대시보드는 Firestore records를 읽기만 한다. 작성·수정은 기존 기록보관실 또는 CPI 분석 저장을 사용한다.
- 관련 목록은 주제·종목의 정확한 일치만 사용한다. CPI 두 시리즈에는 명시적인 CPI 주제를 연결한다. 제목 유사도를 근거로 관련 뉴스라고 확정하지 않는다.
- 원본 지표 정의·수집값·기간별 자료·공식 발표달력을 읽는다. 공식 경로 수집 여부와 원자료 검증은 구분한다. 공식 표시와 FRED/ECOS 경로가 일치하지 않는 값은 숫자를 숨기고 확인 필요로 표시한다. 최신 기간별 자료가 원래 시리즈·단위와 일치하고 더 최근에 수집된 경우 기존 검증 함수를 통해 표시값을 갱신한다.
- 원자료에 OHLC가 없으면 봉을 생성하지 않는다. 기간별 관측 추세와 원자료 표만 표시한다. 공식 정의가 검증된 기준선만 표시한다.
- 선택 자료는 URL 해시에 저장한다. 보기·검색·주제·종류·달력 월·골라 담은 핵심은 별도 localStorage 키 invest.research.dashboard.v1에 저장한다. 핵심 정리는 이 브라우저에만 보관되며 기기 간 동기화가 아니다. 원본 기록은 중복 저장하지 않는다.
- 전체화면에서 돌아갈 때 페이지 배치·스크롤을 복원한다. 좁은 화면에서는 앞 페이지를 접고 상단 탐색으로 이동한다. 지표 파일 또는 Firebase 읽기 실패를 구분하고 다른 영역을 유지한다.
- 이번 범위는 전체 대시보드와 공통 탐색이다. 뉴스레이더 자동 유입, 모든 지표의 장기 데이터 보강, 공통 편집기, 핵심 정리의 클라우드 동기화는 별도 단계다.
# 뉴스레이더 연결 · v019

- 기존 chatgpt/config.json의 newsUrl을 읽어 동일 공급원의 기사 목록을 대시보드에 표시한다. 수집 프로그램·스케줄은 변경하지 않는다. 처음 열 때 읽고 ‘뉴스 새로 읽기’로 갱신한다.
- 레이더 미보관 / 기록보관실 / 지표를 구분하며 같은 8개 보기를 사용한다. 뉴스는 공식 사실 검증 전 수집 자료다. 공급원의 자동 중요도·매매 방향·검증 표시는 가져오지 않는다.
- 기사 발표일은 원문에 시간대가 명시된 경우만 서울 시각으로 변환한다. 피드의 collected_at에는 시간대가 없어 원문과 ‘시간대 미확인’을 표시한다. 화면에서 읽은 시각은 별도로 기록한다.
- 지표별 뉴스 후보는 기존 지표 사전의 키워드 일치와 일치한 단어를 표시한다. 관련성·인과관계가 검증된 자료가 아니며 기존 명시적 연결 자료와 분리한다.
- 기사 주소에서 추적 매개변수와 fragment를 제외한 정규 주소로 중복을 제거한다. 기사 ID는 정규 주소 SHA-256이며 수집 피드의 순번 ID는 쓰지 않는다. 이미 같은 주소를 보관한 기록이 있으면 원본 보관 기록을 우선 표시한다.
- ‘기록보관실에 보관’ 명시 클릭에서만 records에 저장한다. 문서 ID는 radar-SHA256이다. 트랜잭션에서 같은 ID가 있으면 기존 본문·사용자 판단을 그대로 반환한다. 응답 유실 후 재시도도 같은 문서로 확인한다.
- 수집 요약·발췌와 사용자 판단을 분리하고 주제·종목은 임의 지정하지 않는다. source, link, articlePublishedAt, radarKeyword, radarCollector, radarCollectedRaw, importedFrom을 함께 보관한다. 기존 기록보관실에서 후속 분류·메모를 관리한다.
- 뉴스 읽기 실패는 지표·기록보관실에 영향을 주지 않으며 기존 뉴스 목록을 유지한다. 시간 제한 20초, 중복 동시 요청 방지, 수동 재시도를 적용한다. 정상적인 빈 피드와 잘못된 응답 형식을 구분한다.

## v020 · 기존 보기 통합
사용자 승인에 따라 research.html, macro.html, chatgpt/index.html, research-cpi.html은 통합 대시보드로 연결한다. 예전 화면 메뉴를 병렬로 제공하지 않는다. 기존 지표/개인 기록/뉴스 상세 주소는 같은 대상에 매핑한다.

첫 페이지는 지표 카드 또는 뉴스 목록, 두 번째는 선택 자료, 세 번째는 그래프·비교·연결 기사·분석·출처다. 개인 기록 및 기록보관실은 원래 저장소를 사용한다. 세 번째 내용은 최대 하나이며 이전 내용으로 돌아갈 수 있다. 차트와 작성 DOM은 연결을 유지한 채 표시만 바꾸어 입력과 iframe 상태를 보존한다.

연결 원문이 삽입을 막으면 수집 발췌와 명시적인 외부 열기를 유지한다. 국내 네이버 지수는 알려진 삽입 제한을 안내한다. 원자료에 OHLC가 없으면 봉차트를 만들지 않는다. 기존 자료 수집·AI 서버·권한 규칙은 이번 변경에서 수정하지 않는다.
