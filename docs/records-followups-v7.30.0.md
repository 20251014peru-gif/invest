# v7.30.0 — 기록 읽기와 확인·복기

작업일: 2026-09-17. 기준: 배포 v7.29.1(4fd0a44), 최신 main dcbd89c의 자동 자료 갱신을 유지. 다른 앱/저장소는 변경하지 않는다.

## 목적과 사용법

- 기록 제목을 누르면 맨 위 한눈에 보기부터 열린다. 제목·출처/날짜·핵심 한 줄·태그를 압축하고 부가 속성과 내보내기는 접는다.
- 한눈에 보기의 짧은 1~8은 하나의 두 열 영역에 모두 표시한다. 항목마다 누르는 카드가 아니다. 좁은 화면은 한 열이다.
- 화자 점검 / 프레이밍 분석 / 달님 시사점 / 체크 캘린더는 원문의 실제 절 경계로 구분한다. 달님 시사점의 ①~④는 소제목과 문단 간격으로 구분한다. 원문을 다시 쓰거나 삭제하지 않는다.
- 한눈에 보기 / 전체 원문 / 연결 / 확인 기록으로 바로 이동한다. 전체 원문의 문자 내용은 원본과 같다. 목차 이동용 장식은 시각적으로 숨기되 텍스트에 보존한다.
- 오른쪽 위젯은 기존 v7.29.1 자동 숨김을 유지한다. 가장자리 호버/버튼으로 열고 닫으며 기록 영역의 폭을 줄이지 않는다.
- 나중에 탭은 확인·복기로 바뀐다. 질문을 클릭하면 확인 결과 전용창이 열린다. 원문은 연결된 출처 버튼으로 연다.
- 결과 한 줄을 적고 저장하고 완료한다. 완료는 확인 업무의 종료이며, 질문에 적힌 사건이 실제 발생했다는 의미가 아니다.
- 예상/결과/근거 링크·사진/판단 변화/후속 행동을 기록한다. 추가 관찰과 배운 점은 선택 사항이다. 완료·복기에서 다시 열기, 후속 질문, 선택 기록의 공부노트 정리를 지원한다.
- 날짜가 지났어도 미완료는 유지한다. 보류는 별도 목록과 확인 재개 버튼이 있다. 완료 후 재개해도 이전 완료 시점의 이력은 남는다.

## 파일과 연결 경계

- records.html: 기존 목록/오늘 할 일/상세보기와 새 모듈의 연결, 버전. 다른 기록 CRUD 로직은 유지한다.
- js/records-reading.js, .css: 읽기 전용 표시. 기존 본문 필드는 수정하지 않는다.
- js/followups-core.mjs: 이전 항목 식별, 상태 전환, 검색, 백업 형식.
- js/followups-store.mjs: Firestore 트랜잭션, 이력, Storage 업로드.
- js/followups-app.mjs, .css: 목록/전용 편집창/백업 복원/공부노트 정리.
- js/study/study-app.mjs, study-store.mjs, study-editor.mjs: 확인·복기 준비 후 기존 checks를 구형 공부노트 저장이 바꾸지 않도록 좁은 호환 처리. 본문 편집기와 서식 로직은 유지한다.

## 데이터 보존과 전환

새 컬렉션 record_followups(현재 상태), record_followup_reviews(각 저장 시점의 이력)를 사용한다. 원본 records/checks와 records_todos는 전환 과정에서 수정·삭제하지 않는다.

전체 기간 완료 표식을 읽어 기존 질문과 대응한다. 기존 ID가 없으면 질문 내용과 동일 질문의 순번으로 안정적인 ID를 만든다. 원본 질문·전체 완료 표식은 최초 이력에 보존한다. 오래된 완료는 결과를 꾸며 넣지 않고 기존 완료 · 결과 미기록으로 표시한다. 대응되지 않는 완료 표식도 별도로 보존한다. 반복 접속/동시 전환은 트랜잭션으로 중복을 막는다.

버전 충돌 시 다른 기기의 내용을 덮어쓰지 않는다. 저장 실패 시 입력과 기기 초안을 유지한다. 기존 일반 할 일(반복 체크리스트)은 기존 저장 방식을 유지한다.

배포 전 보존본은 Git 밖 작업 폴더 outputs/pre-v7.30-backup에 저장했다. 당시 records 11건, 전체 records_todos 15건, 실제 이미지 4개(누락 0개). 개인 자료/인증 정보는 Git에 넣지 않았다. 이 자료의 격리 시험 전환은 질문 31개, 기존 완료 1개였다. 실제 반영 결과는 배포 검수 기록으로 남긴다.

## 백업과 비용

확인·복기 → 필터·백업 → 전체 확인 기록 백업은 상태/전체 이력/실제 사진/출처 연결/후속 질문 연결을 담는다. 기존 단일 기록 내보내기 및 공부노트 내보내기와는 별도 형식이다. 자료 전체를 보관하려면 각 원문 백업과 확인 기록 백업을 함께 보관한다.

복원은 새 ID를 만들며 기존 항목을 덮어쓰지 않는다. 같은 백업 재시도는 중복 생성하지 않는다. 내부 후속 질문 ID는 새 ID로 대응한다. 원문 연결은 원래 ID를 유지하고 원문이 없으면 표시한다. 파일이 없는 사진은 누락 표시를 남긴다. 한 항목의 이력이 400개를 넘으면 복원 오류로 알리며 몰래 자르지 않는다. 중간 실패 시 이미 복원된 항목을 알리고 다시 시도할 수 있다.

새 AI 호출 없음. 저장은 현재 항목 읽기 1 + 현재 상태/이력 쓰기 2. 최초 접속 시 전체 원본과 전체 옛 완료 표식을 읽고 후보별 트랜잭션 조회를 한다(미전환 후보만 2개 문서 작성). 현재 상태 컬렉션 전체를 실시간 구독한다. 목록의 50개 더 보기는 화면 분할이며 서버 조회 제한은 아니다. 이력은 클릭 때 조회한다. 여러 열린 기기에서 실시간 읽기가 증가한다. 사진과 이력은 자동 삭제하지 않아 누적된다. 대규모 사용 시 구독 분할/조회량 최적화는 별도 과제다.

## 후속 담당자 참고

원문 편집과 확인 결과 편집은 분리한다. 다시 구형 checks 편집을 활성화하거나 완료 표식을 삭제하는 방식으로 되돌리지 않는다. 코어/저장/화면 경계를 유지하고 Claude의 다른 코드에 대한 일괄 포맷/이름 변경은 하지 않는다. scan-app 등은 이번 범위가 아니다.
