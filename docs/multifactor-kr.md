## 계산 (책 2장과 같은 방식, 아래 다른 점만 제외)

- 모멘텀 주가 = (전일+주간+월간+연간 등락률)/4 (거래일 1/5/20/240일 전 종가 대비). 모멘텀 거래량 = 5일/20일 평균 거래량 − 1.
- 밸류 = PER, PBR(연간 K-IFRS 연결, 추정치 행 제외, 최신 확정값). 퀄리티 = 전분기 대비 매출·영업이익·순이익 증가율 + ROE(분기 연결, 추정치 제외).
- 순위(%) = 대상 안의 순위 ÷ 종목 수 × 100. 종합점수 = 선택 지표 순위의 평균(낮을수록 상위). 스타일은 같은 8개 순위 중 일부만 평균: 가치 성장(밸류+퀄리티), 추세 성장(모멘텀+퀄리티), 역발상(밸류+모멘텀).
- **책과 다른 점**: ① PER·PBR이 비었거나 0 이하면 최하위 ② 전분기 값이 0 이하면 증가율 분모에 절댓값, `base_nonpositive` 표시 ③ 동점은 같은 순위 ④ 상장 242거래일 미만 제외 ⑤ 벤처투자사는 종목명 키워드로만 근사.
- 제외: 우선주, 스팩, 리츠, 벤처투자사(근사), 코넥스, 시총 1천억 미만, 주가 1천 원 미만, 20일 평균 거래량 2천 주 미만.
- 설문 문항은 책의 문장을 옮기지 않고 같은 주제를 새로 썼다. A=추세 성장, B=가치 성장, C=역발상(책과 같은 대응이나, 보기 문구는 의미가 맞도록 다시 썼다).

## 합칠 때 해야 할 일

1. `.github/workflows/multifactor-kr.yml`의 임시 `push:` 블록(브랜치 `feature/mf-kr` 한정)을 제거한다.
2. `main`에 합친 뒤 `Actions → Multifactor KR → Run workflow`로 1회 실행해 `analysis/multifactor_kr.json`이 커밋되는지 확인한다(`main`에서의 커밋·push 경로는 아직 실행해 보지 않았다).
3. 허브 화면에서 `multifactor.html`로 가는 링크를 추가할지 결정한다.

### 미검증·위험
- **휴대폰 실기기·외부 이동통신망 접속**: 미검증. 브라우저 에뮬레이션(375px)에서만 확인했다.
- **수치의 정확성**: 공식 자료(DART 등)와 대조하지 않았다. 이익이 작은 기업의 극단적 증가율, 기저 효과, 일회성 이익이 그대로 반영된다.
- **데이터 출처 약관**: KRX 목록과 네이버 재무 스냅샷은 비공식 경로이며 이용 약관 해석을 확인하지 않았다. `HOME_HANDOFF.md`의 종목 조회기 항목에도 "저장·재배포는 별도 확인 필요"라고 적혀 있다. **결과 JSON은 GitHub Pages로 공개 서빙되므로, 파생 값이라도 공개 재배포에 해당하는지 판단이 필요하다.** 공개가 부담스러우면 결과를 로그인 뒤 Firestore에 두는 방식(기존 Firebase 재사용)으로 바꿀 수 있으나 아직 하지 않았다.
- **1,000종목 규모**: 시험하지 않았다. 처음 설계 기본값은 200종목이다.
- **시장 국면·스타일별 성과**: 이 점수가 실제로 초과수익을 냈는지는 백테스트하지 않았다.
