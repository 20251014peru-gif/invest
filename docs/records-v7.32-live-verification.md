## 실제 시험에서 수정한 문제

1. Firestore의 일반 조회와 트랜잭션 조회에서 객체 키 순서가 달라 사진/출처 필드를 실제 충돌로 오인할 수 있었음. 객체는 키 순서와 무관하게 비교하고 배열 순서는 유지하도록 수정. 실제 재수정 성공과 실제 충돌 거절을 다시 확인.
2. 저장 확인과 실시간 수신 순서에 따라 일반 기록 읽기 창에 이전 본문이 남는 문제. 일반 기록의 버전 변화도 수신 시 갱신하도록 수정.
3. 백업 HTML을 `file:`로 열면 모듈이 시작되지 않는데 로그인 확인 중으로만 보이던 문제. 웹 주소로 열라는 안내와 운영 링크 표시.

## 운영·복구와 남은 범위

- 공식 주소: https://20251014peru-gif.github.io/invest/records.html
- 화면은 기존 GitHub Pages, 저장은 기존 Firestore/Storage. 새 유료 서비스·서버·예약 작업·AI 호출은 추가하지 않음. 기존 읽기/쓰기·저장·전송 사용량은 발생.
- 개발 시험 서버 `localhost:8925`는 시험 도구다. 운영 실행에 필요하지 않다.
- 배포 전 운영 코드 기준 `4cb982d`를 보존한다. 코드 문제 시 이번 기능 변경을 revert하여 Pages에 재배포한다. 원본 데이터를 통째로 덮어쓰거나 삭제하는 복구는 하지 않는다.
- 백업 JSON은 기록보관실 5개 컬렉션의 원본 ID·필드·연결을 보관한다. 전체 Firebase 프로젝트 백업이나 원클릭 복원 도구는 아니다. 복구 시 백업과 현재 서버를 대조한 뒤 필요한 문서만 보존된 ID로 복원한다.
- 사진 선택 자동화는 Chrome 확장 프로그램의 파일 접근 권한으로 제한됐고 붙여넣기로 실제 업로드를 검증했다. 실제 휴대폰의 사진 선택·촬영은 미검증.
- 개발 주소에서 사진 백업 `fetch`는 Storage CORS 응답 때문에 실패했다. 백업에 누락을 명시한다. 기존 원본에 사진은 없었고 시험 PNG 원본은 따로 보관했다. 사진 표시 성공을 사진 파일 백업 성공으로 간주하지 않는다.
- 기존 유튜브 기록 5건의 원본 링크에 `localhost:5055`가 남아 있다. 기록 내용 조회·수정과 별개로 그 과거 원본 링크는 다른 기기에서 열 수 없다. 원본 데이터 보존을 위해 이번 시험에서 임의로 URL을 바꾸지 않았다.
- 실제 휴대폰·외부 이동통신망은 미검증. PC 독립 운영의 전체 완료를 주장하지 않는다.
- C 단계(매매 원장·자동 보유수량·평균단가·손익 계산)와 다른 프로그램 통합은 이번 배포 범위가 아니다.
