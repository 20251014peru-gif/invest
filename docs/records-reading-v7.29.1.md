## 사용 동작

1. 위젯은 기본 숨김. 오른쪽 ‘위젯’ 손잡이에 마우스를 올리면 왼쪽으로 펼쳐지고, 벗어나면 닫힌다. 클릭/터치로 열면 유지되며 닫기·Escape·바깥 클릭으로 닫힌다. 위젯 내부에 입력 포커스가 있으면 마우스만 벗어나도 닫히지 않는다.
2. 닫혀 있을 때 목록이 전체 폭을 사용한다. 열릴 때만 목록 위로 잠시 겹친다. 위젯별 접기 상태와 할 일 기능은 기존 것을 그대로 사용한다. 이전 사이드바 숨김 설정은 새 자동 숨김 방식에서 사용하지 않는다.
3. 목록에서 기록을 열면 제목부터 시작하고 ‘내용’ 탭이 선택된다. ‘연결된 기록’과 ‘나중에 볼 것’은 각각 별도 탭이다. 관계 갱신/공부노트 실시간 갱신으로 같은 화면을 다시 그릴 때는 선택 탭과 스크롤을 보존한다.
4. 읽기 하단에 닫기를 추가했다. 수정은 기존 수정 버튼을 눌러 진입하며 일반 수정창도 위에서 시작한다. 상세보기 내부 본문의 별도 세로 스크롤은 없애고 모달 하나로 읽는다.
5. `01`~`09`처럼 번호만 한 줄에 있는 연속 목차는 PC 2열/좁은 화면 1열 카드로 보여준다. 항목 선택 시 하나만 펼친다. 뒤에 같은 제목의 상세 절이 명확히 있으면 그 절을 보여주며, 매칭이 안 되면 목차 요약과 ‘전체 원문’ 안내를 보여준다. 문서 구조를 인식하지 못하면 바로 전체 원문을 표시한다.
6. ‘전체 원문’은 저장된 텍스트 전체를 그대로 표시한다. 전체 복사/내보내기 로직도 유지한다. 자동 요약, 원문 재작성, DB 변환은 하지 않는다.

- 기존 records-core/study-core 27개 및 신규 읽기 단위 시험 4개 통과.
- 기존 공부노트 브라우저 회귀 시험 6개 통과.

## 데이터 / 제한

데이터 모델·저장·사진·수정 이력·검색·필터·백업·연결 쓰기 방식은 그대로다. DB 마이그레이션이나 추가 API 호출은 없다. 목차 인식은 안전한 제한 범위에서만 수행하므로 모든 자유 형식 문서를 카드로 바꾸지는 않는다. 실제 휴대폰과 개별 운영 문서의 상세 절 매칭은 미검증이며 전체 원문을 항상 제공한다.
