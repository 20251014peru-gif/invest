## 사용자가 정한 방향

- 별도 프로그램을 만들고 합치지 않고, 기존 투자 기록보관실 안에서 개발한다.
- 기존 **종목 탭 → 종목 목록 → 종목명 클릭**을 입구로 쓴다. 별도 B/C 탭을 만들지 않는다.
- 2026-09-22 변경 요청: 종목 요약·판단 기준·다음 확인을 PC 3열로 보여준다. 완료·복기는 다음 확인 안에서 펼친다. 입력은 순서가 보이는 2~3열, 출력은 가로 공간을 활용한다.
- 같은 일은 한 곳에서 입력하고, 종목·오늘 할 일·달력·확인·복기가 동일한 확인 항목을 참조한다.
- 겹치는 입력창을 줄이되 원본 기록·사진·공부노트·관계 연결 등 고유 기능을 보존한다.
- 종목 정보의 추가/수정/삭제는 한 번에 저장. 새 투자논지는 기존 기록 편집기로 남긴다. 과거 직접 입력한 투자논지와 자동 변경 이력은 유지한다.
- PC/모바일과 출력 화면을 고려한다. 완료는 확인 업무 종료이며 예상의 적중을 의미하지 않는다.
- 먼저 B(기록·확인·복기 사용성 통합). C(실제 매매 원장과 자동 수량/평단/손익 계산)는 후속 단계다. 현재 수량과 단가는 사용자가 적은 값이다.
- 독립적인 종목 분석 프로그램 등은 유지한다. 공시와 이벤트 연구의 결합은 후속 작업이며 이번에 다른 프로그램을 삭제하지 않았다.
- 뭔가를 수정하기 전에 사용자에게 변경 방법을 먼저 설명한다.

## 개발본에 반영한 내용

1. 종목 요약/판단 기준/다음 확인을 나란히 배치하고 완료·복기는 확인 패널 안에, 기록·변경 이력은 아래에 둔다.
2. 기록, 종목 정보, 확인·복기의 실제 기존 입력 DOM을 하나의 지속되는 입력 공간에서 사용. 목록 재렌더 중에도 입력이 유지된다. 읽기 창에서 수정한 뒤 원래 읽기 화면으로 돌아간다.
3. 자유 항목 추가·삭제를 임시 반영한 뒤 저장. 같은 필드 충돌 시 덮어쓰기 거절. 기존 원본과 이력 보존.
4. 종목에서 만든 확인 질문의 종목 태그 저장, 후속 질문 상속, 원본 연결로도 종목에 표시.
5. 달력의 확인 일정은 `record_followups`의 현재 미완료 예정일 사용. 완료·보류는 예정 목록에서 제외. 기록 자체의 날짜는 기존대로 표시.
6. 기존 기록의 원본 `checks`는 편집 창에서 보존. 현재 일정은 확인·복기에서 수정. 미래의 공부노트 재검토일도 기존 마이그레이션 방식으로 확인 항목에 연결한다.
7. 일반 기록 저장에 고정 문서 ID, 저장 중 중복 클릭 방지, 트랜잭션 충돌 감지와 실패 시 입력 보존 추가.
8. 저장된 내용의 출력 미리보기. 종목 정보, 확인 결과, 일반 본문, 첨부 사진을 표시. 출력에서 조작 버튼 제외. 공부노트 서식/관계도와 확인의 세부 변경 이력은 원본에서 보는 요약 출력이다.
9. 상단 종목 관리 입구는 기존 종목 목록으로 연결. 종목 등록과 내용 없는 이름 정리는 목록 안에서 사용.

주요 파일: `records.html`, `js/records-stocks.js`, `js/records-stock-workflow.js`, `js/records-workspace.js`, `js/records-workspace.css`, `js/followups-app.mjs`, `js/followups-core.mjs`, `js/followups-store.mjs`.

## 집 PC에 처음 받기

Git과 Node.js가 설치된 PowerShell에서 본인이 관리할 개발 폴더로 이동한 뒤 실행한다.

```powershell
git clone --branch codex/records-unified-workflow --single-branch https://github.com/20251014peru-gif/invest.git
cd invest
node tests/study-browser/server.cjs 8923
```

브라우저에서 http://localhost:8923/tests/study-browser/workflow-demo.html 을 연다. **이 주소는 개발 시험 전용**이며 예시 자료를 사용한다. 운영 Firebase에 접속하지 않도록 Firebase SDK를 시험 대역으로 바꾼 서버다. 실제 자료로 착각하지 않는다. Node를 멈추면 이 시험 화면도 멈춘다.

Codex에서는 내려받은 `invest` 폴더를 프로젝트로 열고 위의 이어가기 문장을 입력한다. 같은 폴더를 여러 PC에서 OneDrive로 동시에 수정하기보다, 각 PC의 별도 복제본에서 Git으로 주고받는다.

기존 복제본이 있으면 우선 `git status`로 저장하지 않은 작업을 확인하고 보존한다. 이후 `git fetch origin`, `git switch codex/records-unified-workflow`, `git pull --ff-only`로 맞춘다. 로컬 변경을 강제로 지우거나 원격 브랜치를 강제 덮어쓰지 않는다.

## 시험

Node 내장 시험은 외부 설치 없이 실행한다.

```powershell
node --test tests/records-stocks.test.cjs tests/followups.test.mjs tests/records-backup.test.mjs tests/records-core.test.mjs tests/records-reading.test.cjs
```

브라우저 시험은 Playwright가 있는 환경에서 시험 서버를 켜고 실행한다. Windows는 Edge, 다른 OS는 Playwright Chromium을 사용한다. 필요한 경우 별도 시험 환경에 Playwright를 설치한다. 회사 PC의 절대 패키지 경로를 집 PC에 복사하지 않는다.

```powershell
node tests/records-workflow.browser.cjs
node tests/followups.browser.cjs
```

`tests/study-browser/stocks-regression.html`도 시험 서버에서 열어 결과를 확인한다. 캡처 결과는 `test-results/records-workflow/`에 생성되며 Git에는 넣지 않는다. 실제 소유자 로그인/보안 규칙 시험과 휴대폰 실제 기기 시험은 이 대역 시험으로 대체되지 않는다.
