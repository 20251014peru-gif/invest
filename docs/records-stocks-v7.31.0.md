## 원인과 변경

`records_meta/stocks.list[].thesisLog`의 직접 입력 논지/자동 변경 이력과 `records`의 종목 태그 연결 기록은 서로 다른 데이터다. 이전 `stockCount`와 `stockRecords`가 후자만 세고 표시했으므로 논지가 있어도 0건/빈 화면이었다. 최신 활동 날짜는 논지를 포함하면서 기록수는 제외해서 모순돼 보였다.

종목 화면에서 두 원본을 읽기 전용으로 합쳐 표시한다. 원본 문서의 이동, 자동 복제, 삭제, 일괄 마이그레이션은 없다. 기존 기록은 원래 상세보기로, 종목 이력은 전체 텍스트 읽기 창으로 연다. 현재 보유수량/매수단가/목표가/자유 항목은 개별 종목 상단에 표시한다. 목록은 최근 내용 미리보기 중심으로 바꿨다.

- 내용 있는 종목만 기본 표시. 체크를 풀면 이름만 있는 종목도 조회 가능. 내용 유무 → 최근 날짜 → 같은 날짜의 시각 → 이름 순서.
- 종목 안에서는 날짜 내림차순. 새 이력은 밀리초 시각 `at`도 저장. 과거 이력에는 시각을 만들어 넣지 않고 같은 날 배열의 뒤쪽 항목부터 표시한다.
- 전체 종목 버튼, 종목 선택 상자, 이전/다음 버튼. 목록으로 돌아갈 때 스크롤 위치 보존. 종목 탭을 다시 눌러도 전체 종목으로 돌아온다.
- 종목 화면에서 새 기록을 작성하면 해당 종목을 미리 연결. 사용자가 저장할 때까지 새 기록은 생성하지 않는다.
- 상단 검색은 종목명, 연결 기록, 논지, 자유 항목에 적용. 선택한 종목에서는 전체 이력을 표시한다고 안내. 종목 모드에서 적용되지 않던 일반 기록 필터는 숨긴다.
- 좁은 화면에서는 종목 목록과 개별 기록 표를 세로로 배치해 날짜/제목/내용부터 보인다. 원문은 눌러서 열 수 있다.
- 종목 저장은 서버 최신 문서를 읽는 Firestore 트랜잭션으로 병합. 같은 필드 충돌은 거절하며, 같은 브라우저의 연속 저장은 직렬 처리한다. 서버 확인 후 성공 표시, 실패하면 입력 보존. 내용 있는 종목의 전체 삭제 버튼은 노출하지 않는다.
- 한국 시간 오전에 저장 날짜가 전날로 기록될 수 있던 `todayStr()` 시간대 계산도 수정.
- 자료 구독 실패는 0건과 구분하여 화면에 알린다.

## 검증과 한계

Node 단위/회귀 52개 통과. 격리 브라우저 시험 18개 통과(원본 불변, 이력 합산, 같은 날 정렬, 원문 열기, 전체/개별 이동, 이름만 있는 종목, 자동 태그, 저장 실패/성공, 연속 추가, 충돌 거절). `tests/study-browser/server.cjs 8923` 실행 후 `/tests/study-browser/stocks-regression.html`에서 재현. 이 서버는 Firebase SDK를 시험 대역으로 교체한다. 운영 자료와 접속하지 않는다.

PC 브라우저의 데스크톱/390px 화면으로 검수한다. 실제 휴대폰, PC 의존을 차단한 외부망에서의 인증·조회·저장·사진·재접속 종합 시험은 미검증이다. 운영 새 브라우저 창에서 기존 v7.30.0의 records 구독이 `Missing or insufficient permissions`로 실패했다. 원인은 2026-09-18 배포된 Firestore 규칙이 `records`를 소유자 Google 계정으로 제한했는데 기록보관실은 익명 로그인을 계속 사용한 인증 방식 불일치였다. v7.31.1에서 익명 로그인을 제거하고 명시적인 본인 Google 로그인 버튼으로 맞췄다. 규칙은 완화하지 않는다. 로그인 후 운영 데이터 전체 대조와 새 버전 실자료 저장 시험이 필요하다. 합성 시험의 성공을 운영 완료로 해석하지 않는다.

## 운영·보존·비용

GitHub Pages와 기존 Firebase `my-system-25497`를 유지한다. 종목 정보/이력 기준본은 Firestore `records_meta/stocks`, 연결 기록은 `records`, 사진은 기존 Firebase Storage 경로다. 이번 변경에 AI 호출, 예약 작업, 새 클라우드 서비스, localhost 운영 의존성은 없다. 화면 투영은 브라우저에서 수행하고 새 저장은 Firestore가 확인해야 완료된다. 트랜잭션은 읽기/쓰기 및 충돌 재시도 비용이 발생할 수 있다. 사용량 제한/가격의 현재 상태는 별도로 확인해야 한다.

코드 원본은 위 Git 커밋과 로컬 보존 브랜치에 남긴다. 롤백은 이번 변경 커밋을 revert하여 Pages 재배포. 사용자 문서의 스키마/기존 값을 이동하지 않았으므로 역마이그레이션은 없다. 단, 구버전은 다시 논지를 목록에서 숨기며 예전 저장 경합 위험이 돌아온다. 추가한 `at` 필드는 구버전이 무시한다.

실자료 백업을 확보했다고 주장하지 않는다. 기존 일반 기록 파일 내보내기는 종목마스터 전체를 포함하지 않는다. 종목 데이터의 완전 백업에는 Firestore `records_meta/stocks` 원본이 별도로 필요하다. 장기 개선: 소유자 계정의 여러 기기 인증/권한 검증, 종목 이력 개별 문서화와 종목 전체 백업·복원. 현재 모든 종목과 이력이 한 문서에 쌓이므로 무한 누적을 보장할 수 없다. Firestore 문서 한도는 1 MiB다. [공식 한도](https://firebase.google.com/docs/firestore/quotas), [공식 트랜잭션 동작](https://firebase.google.com/docs/firestore/manage-data/transactions).

## 후속 개발 원칙

사용자의 2026-09-18 PC 독립 원칙을 계속 적용한다. 기존 클라우드/버전부터 확인하고 화면·실행·저장·예약·첨부 의존성을 구분한다. 운영에 PC 주소/임시 디스크 단독 저장을 도입하지 않는다. 인증·소유권·비밀키·비용을 서버에서 보호한다. 원본 백업, 시험환경, 데이터/사진 대조, 최종 차이 반영 및 복구를 준비한 뒤 구조를 이전한다. 기존 기능/자료를 조용히 제거하지 않는다. 장기 처리는 클라우드에서 완료하고 기기를 바꿔도 결과를 조회할 수 있어야 한다. PC 전용 기능은 공식 API 대체 가능성과 남는 비용/제약을 명시한다. 실제 휴대폰 시험 전까지 완료라고 보고하지 않으며 주소/버전/저장 위치/예약 실행 위치/복구/비용/미검증을 인계한다.
