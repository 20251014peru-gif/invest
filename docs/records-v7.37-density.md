# v7.37.0 읽기 2열·목록 간격

2026-09-27 13:50:45 KST. 사용자 사진에서 목록 행이 지나치게 높고, 한눈에 보기의 긴 시사점은 여전히 한 열인 문제를 확인했다.

원인: 목록 셀 위아래 22px, 항목 사이 14px, 소제목과 본문의 별도 줄, 별점 별도 줄이 누적됐다. 읽기는 개요 카드만 2열이고 긴 시사점은 전체폭 단일 열이었다.

수정: 셀 위아래 10px, 항목 간격 6px, 소제목과 본문 인라인, 날짜·채널·별점 한 줄. 16px 본문과 전체 내용은 유지한다. 한눈에 보기의 긴 본문도 텍스트 2열이며, 원문은 소제목 섹션 2열과 비구조 본문의 2열을 지원한다. 900px 이하에서는 모두 1열이다. 원본 글자·순서·저장 데이터·분류·필터는 변경하지 않는다.

검증: 읽기 단위 시험 6개 통과. `tests/records-density.browser.cjs` Firebase 대역에서 1440/1024px의 두 탭 2열, 390px 1열, 원문 textContent 일치, records 불변, 가로 넘침·JS 오류 없음 확인. 동일 시험 기록/1440px에서 이전 간격 규칙 대비 행 높이 162.66→93.5px(43% 감소). 모든 실제 기록에 동일 비율을 보장하는 수치는 아니다. 실제 개인 자료 쓰기는 하지 않았다.

복구: 기준 b545b06의 records.html 및 js/records-reading.js/css로 코드만 복귀. 데이터 변경·새 서버·AI 호출 없음. 기존 GitHub Pages 운영 배포는 해당 커밋의 실행 결과로 확인한다.

교훈: 열 수뿐 아니라 각 셀의 라벨·본문·메타데이터 줄 수와 누적 여백도 실제 화면 밀도를 결정한다. 고정 높이·내용 잘라내기 대신 먼저 불필요한 줄바꿈과 여백을 줄인다.
