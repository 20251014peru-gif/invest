# 매크로 관측실 구조

첫 범위: 지표 조망 → 주소가 있는 상세 페이지 → 그래프·정의·관계·뉴스·개인 기록.

## 자료 흐름
- 기존 invest/data/indicators.json: 지표 정의, 단위, 수집 주기.
- 기존 invest/facts/macro.json: 최근 값·이전 값·기준일·설정 판정.
- 기존 invest/facts/macro_history.json: 수집일별 스냅샷. 발표 이력과 다름.
- 기존 루트 사이트 news.json: 네이버·구글 뉴스. 주소 중복 통합, 키워드 후보 연결.
- 새로운 개인 기록: Firestore의 chatgpt_macro_private/{본인UID}/records/{UUID}. 원본과 수정판을 같은 트랜잭션에 저장. Google 본인 인증과 서버 권한 설정 완료 후 활성화.
- 입력 중 초안: 이 기기의 IndexedDB. 온라인 저장 전에는 다른 기기로 동기화되지 않음.

## 고유 주소
- 지표: #/indicators/{고정ID}
- 뉴스: #/news/{정규화한 원문 주소의 해시}. 현재 수집 파일에서 기사가 사라지면 주소만으로 복원 불가. 장기 아카이브는 후속 단계.
- 기록: #/records/{UUID}
- 지표 관계는 양쪽 지표 ID, 관계 종류, 근거 주소, 작성 내용을 저장.

## 기능 격리
core.js(숫자·시각·정규화), catalog.js(정의·조건부 해석), chart.js(차트), storage.js(개인 기록), app.js(화면 흐름).
뉴스 또는 저장소가 실패해도 지표는 유지. 미수집 값은 0으로 대체하지 않음. 실패한 입력은 지우지 않음. 동시 수정 충돌은 덮어쓰지 않고 재확인을 요청.

## 배포
기존 프로그램과 별도 chatgpt 경로. 기존 수집기를 재사용하며 기존 앱 코드는 변경하지 않는다. build.mjs가 버전별 자산을 만들어 이전 캐시와 섞이지 않게 한다. release.json은 화면 버전의 원본. GitHub 커밋을 복원해도 개인 기록은 별도 저장소에 유지.

## 다음 확장
충분한 실제 시계열 → 시점별 경기 국면·과거 사례 비교 → 산업·종목 → 공시·수급·EPS 시나리오. 관측 당시 자료와 나중에 수정된 자료를 분리해야 사후정보로 과거 판단을 꾸미지 않는다. 역사 반복은 검증할 가설이며 결과를 미리 확정하지 않는다.
현재 앱의 AI API 사용은 0. 검색·단순 계산·키워드 연결은 로컬 처리. AI가 필요한 원문 분석만 새 자료에 한해 저장·재사용하는 방식으로 추가한다.

## v002 확장
- lens.js: 목적별 확인 순위, 뉴스 분야 후보 분류, 기준일/누락을 검토한 규칙 요약.
- ai.js: 기사 요약/전체 질문 UI, 선택한 근거 전송. 키를 보관하지 않음.
- backend/: 본인 Firebase 토큰 검증 후 OpenAI 호출, 개인 경로 캐시와 서울 일별 호출 상한. 배포/연결 대기. API 선택은 OpenAI로 사용자 확인.
- 상세한 연결 순서는 backend/README.md. 실제 인증·키 확인·거절 검사 전 aiEndpoint는 빈 값 유지.

## v003 연결
AI 서버와 본인 기록 접근 제한 배포 완료. 기존 'API 사용0/배포대기'는 v001/v002 당시 상태다. v003은 사용자가 AI 요청 시 서버가 OpenAI를 호출한다. 무인증 차단 검사 완료. 실제 브라우저 본인 호출/동기화는 후속 검사.


## v005 뉴스 노트
notebook.js는 기사별 작성기와 독립 노트 팝업을 관리. 기존 private records에 kind=news-note, targetId=기사ID, snapshot=기사 제목·출처·날짜를 저장. 기존 저장 트랜잭션과 revision 하위 이력 재사용. 전체 검색과 내 메모 목록, records 고유 주소에서 접근. AI 답변을 사용자가 명시적으로 메모에 넣을 때만 기록에 포함. IndexedDB 초안은 기사/수정대상별 분리. 서버 규칙·AI 함수 변경 없음.

## v006 읽기·쓰기 배치
뉴스 요약 모달만 2열 그리드. 읽기와 노트 영역은 독립 스크롤, 작은 화면은 CSS 전환으로 같은 입력 DOM을 유지한다. 전체 질문 모달과 독립 노트 모달은 기존 배치 유지.

## v007 현재 시장 우선 조망
- observatory.js: 고정 핵심 6개, 최신성·변화 폭·수집 이력 변경에 따른 최대 4개 승격, 부족한 슬롯의 시장 보완, 6개 분야 분류, 기존 설정 판정의 5축 요약. 순수 함수로 자동 검사.
- app.js: 기본 시장판과 분야별 접힌 목록에 각 지표를 한 번만 표시. 기존 필터·정렬은 전체 자료를 대상으로 적용. 전체 펼치기/접기와 카드 설명 펼침. 기존 상세 주소·차트·뉴스·개인 기록 유지.
- 종합 해석의 근거와 조건은 기존 lens.js 내용을 상세 펼침 안에서 재사용. 수집 시각을 발표 시각으로 취급하지 않으며 예상치 서프라이즈를 생성하지 않음.

## v008 웹 장기 그래프
- chart-sources.js: 35개 원지표별 외부 차트 경로와 제약. FRED 파생지표 4개는 단위가 보존되는 공식 공유 그래프 사용.
- 카드 제목·웹 차트 링크는 기존 외부 팝업 설정 사용. 설명·뉴스·기록은 기존 상세 주소 유지. 상세 상단 차트 링크, 수집 스냅샷은 기본 접힘.
- 전체 대조표: CHART-AUDIT.md. 데이터 수집과 개인 저장 로직 변경 없음.

## v009 카드 클릭 수정
카드 제목의 확장 클릭 영역은 내부 상세 주소만 사용한다. card-chart-actions와 card-details는 상대 위치·z-index 2로 제목 덮개보다 위에 배치한다. 외부 차트는 전용 링크에서만 연다.

## v010 실제 차트 삽입

- page에서 mount, route 전환·dialog close에서 dispose. 네이버 타이머 해제, 이전 차트 DOM 제거. 외부 차트 실패시 웹 차트 링크 유지.
- 수집 그래프·비교는 누적 데이터·출처 확인 안에 보존. 카드와 제목은 내부 상세 유지.
